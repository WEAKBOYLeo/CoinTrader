### 实现假设及验证方法

1. **历史数据复用以 K 线和资金费历史为首要范围**，并沿用 DiskCache JSON，不引入新的数据库或列式文件依赖。验证：逐一检查 data API 参数与已有 cache key；设计区间清单/分段 key 能够无歧义表达时间边界和 closed-only 语义。

3. 订单前报价已有 `Quote` 包含两腿价格与时间；可以通过扩展兼容字段或不可变领域 quote snapshot 记录来源、接收时间和市场时间，而不改变价格/下单选择。验证：读取 `live.strategy.Quote`、`domain.market`、OrderPlanner 的当前构造与测试；必须保持公开 CLI 和 PairExecutor 接口兼容。
4. 控制台本轮指 CLI status 与现有 WebUI `/api/state`，不增设新 HTTP 服务。验证：查询只依赖 QueryService/read model；健康内存字段明确 source/as_of，缺失状态返回 UNKNOWN。
5. 同 IP 外部流量无法被进程内精准分配；目标仅是显示服务端 observed weight、配置预算、响应缺失/异常和 429/418 次数，并把“其他进程造成的余量不确定”显式呈现，不建立虚假的精确 attribution。

## 4. 目标架构与数据流

### 4.1 数据类别与 ownership

```text
Historical API request (market, symbol, interval, [start,end), schema)
  -> coverage index lookup
  -> cache hit intervals + missing intervals
  -> BinancePublicClient (shared RateLimitCoordinator)
  -> validate/page/normalize/dedupe
  -> atomically persist segment + atomically update coverage index
  -> HistoricalDatasetResult(coverage, gaps, quality)

Live QuotePort / existing Quote adapter
  -> validate both leg prices/timestamps/source
  -> QuoteSnapshot freshness/skew gate
  -> proposal/intent (existing production chain)
  -> risk -> plan -> execution (unchanged)

RateLimitCoordinator snapshots + cache/quote health
  -> LiveService health snapshot (diagnostic only)
  -> CLI/WebUI Query/read model
  -> status values with source + as_of + quality (read-only)
```

- `DiskCache` 继续拥有文件写入、原子替换和格式版本；data repository owns coverage metadata and segment selection。
- `RateLimitCoordinator` 继续唯一拥有 process rate state；adapters 仅 observe 和导出 snapshot。
- Quote adapter owns source normalization; application/live gate owns deciding if new-risk action can proceed; OrderPlanner remains consumer, not freshness authority.
- LedgerQueryService owns authoritative SQLite read queries; ephemeral service snapshot owns process health only. UI never mutates these sources.

### 4.2 历史区间读写协议

1. Normalize request to a canonical half-open interval `[start_ms, end_ms)`; define how final/open candle is excluded using interval close timestamp and exchange time.
2. Canonical coverage key includes exchange, market, symbol, endpoint/data kind, interval, schema/cache format; query parameters that alter response semantics are included.
3. Coverage records only validated complete segments. Empty response is recorded complete only when request bounds are valid and endpoint semantics prove no records; transport/parse/rate errors never advance coverage.
4. Subtract persisted complete segments from requested interval. Missing intervals are paginated using existing endpoint limits/weight; retain existing small-page funding rule and `KLINES_MAX_LIMIT`.
5. Normalize, sort and dedupe by exchange candle open timestamp or funding event identity; persist immutable segment atomically before updating coverage index. A crash between writes leaves an unindexed segment (safe orphan), never falsely marked coverage.
6. If index is corrupt/missing/schema-old, rebuild conservatively from verifiable segment metadata; if complete coverage cannot be proven, treat it as gap and refetch. Never infer coverage from file existence alone.
7. Concurrent requests for same key must not publish partial coverage. Either use bounded in-process single-flight already present at client/repository boundary or prove atomic index merge; cross-process guarantees are not claimed unless implemented/tested. If user processes can race unsafely, stop and propose a lock design.

### 4.3 实时报价契约和 gate

`QuoteSnapshot` (new immutable value or compatible extension to current Quote) has at minimum:

- `symbol: str`, `spot_price: Decimal`, `perp_price: Decimal` (must be > 0).
- `spot_exchange_ts_ms: int | None`, `perp_exchange_ts_ms: int | None`, `received_at_ms: int`.
- `source: str` from finite values already supported by adapters (`rest`, `stream`, `test/fake`); production cannot label unknown source fresh.
- `connection_generation: str | int | None` when stream transport supports it.
- `quality: FRESH|STALE|INCOMPLETE|INVALID|DEGRADED`; no freshness inferred from construction time alone.
- Derived `max_leg_age_ms` and `skew_ms`, evaluated against injected server-adjusted now.

Before OPEN/RESIZE that increases risk: both prices positive, timestamps present/credible per source contract, each leg age `0 <= age <= max_market_data_age_seconds * 1000`, skew within existing quote-skew config, quote symbol equals intent symbol, quality FRESH, account/reconcile/safety gates allow. Failure records a rejection/alert and performs zero broker submissions. CLOSE/reduce-only retains existing conservative behavior and is not blocked by entry-only freshness gate without explicit policy; it still records quote quality.

- `src/cointrader/config.py::ExecutionConfig.max_market_data_age_seconds`: `float`, default `5.0` seconds, must be `> 0`; loaded from `execution.max_market_data_age_seconds`; read-only in this plan.
- `src/cointrader/config.py::ExecutionConfig.max_quote_skew_ms`: `int`, default `500` ms, must be `>= 1`; loaded from `execution.max_quote_skew_ms`; read-only in this plan.

### 4.4 限流与查询控制流

- Keep exact current request scope, priority, caps, freezing, ban and retry behavior.
- Add/extend a sanitized diagnostics model whose timestamps are wall-clock UTC ms for UI plus monotonic values only for internal elapsed calculations.
- Report `observed_used` as server response observation, `local_used` as local estimate, `header_age_ms`, `in_flight`, `waiting_by_priority`, `frozen_until/ban_until` status, `freezes/bans/diagnostic_errors`, and `external_usage_uncertain=true` when process cannot account for all same-IP traffic.
- Do not expose URLs, signatures, API keys, listen keys, or request params.
- WebUI/CLI consume health diagnostics as a separate labeled block from authoritative ledger status. If diagnostics unavailable, return UNKNOWN/null + error state, not 0/healthy.
- WebUI calls remain read-only and fault-isolated; no rate coordinator acquire or Binance API call from query handlers.

## 5. 技术栈与关键契约

## 9. 安全、性能、兼容与回滚

### 输入与敏感信息

## 10. 偏离与停止规则

### 允许的小偏差

- 在同一列明模块内重命名私有 helper、拆分测试 fixture、使用等价 frozen dataclass/Protocol；不改 public method、数据语义、文件范围或 AC。
- coverage namespace/key 的内部字符串与本计划不同，只要版本化、无碰撞、half-open coverage 证明不变量不变。
- UI 使用现有 payload 结构而非字面 `{value,source,as_of,quality}`，只要字段可机械映射并且 UNKNOWN/权威等级不丢失。
- 每个小偏差必须追加开发日志：原因、影响文件、验证命令和结果。

### 重大偏离（记录后停止）

- 新增运行依赖、外部存储、SQLite schema migration、跨进程锁或新守护线程。
- 改 Binance 请求 scope、weight、优先级、retry、freeze/ban、现有 API host 或配置额度。
- 改交易策略/资金费口径、订单价格类型、下单顺序、平仓/reduce-only 规则或现有风险审批。
- 变更公共方法返回结构、删除 CLI/API 字段、重命名公共文件或删 cache namespace。
- 把 WebUI 变为有交易写能力，或让 cache freshness 推翻 quote freshness。
- 改本计划外安全/部署文件，或要真实联网交易、主网/测试网下单、VPS 操作、sudo、push/deploy。
- AC 需改写才能通过，或将“不可保证 0 429”改成绝对保证。

### 阻塞（记录后停止）

- 用户未提交修改与目标文件无法安全分界。
- skew/freshness 配置事实与计划不一致；应停止，而非创造默认阈值。
- 缓存 coverage 并发无法证明无假完整，或 endpoint 时间边界未知。
- 测试、ruff、mypy、doctor 无法执行或失败无法在范围修复。
- 需要删测/skip/xfail/吞错误/伪造来源或跳过真实成交一致性才能推进。
- 发现现行生产 chain/Quote contract 与计划事实不符，需重新设计。

执行模型无权自行批准重大偏离或修改计划；等待用户/计划作者批准新版本。
