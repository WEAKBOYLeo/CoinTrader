### 已确认事实（均来自仓库检查）

1. **代码中不存在任何 7 天/时长上限**。`LiveService.run_forever()`（`src/cointrader/live/service.py`）是 `while not stop_check(): run_once(); sleep(tick)`，只会被 Ctrl-C、KILL_SWITCH 文件或异常退出停止。
2. **上次"停止"的真实原因：进程被外部终止且无人/无机制拉起。** `data/live/trading.sqlite3` 的 `run_sessions` 表有 4 条记录全部 `ended_ms=NULL`（状态 `RUNNING`/`RECOVERY`），说明进程全部非优雅退出（kill/断电）；`end_run_session` 只在 `stop()`（Ctrl-C）路径被调用。
3. 当前部署方式是 **tmux 手工运行**（`docs/开发日志.md`：`tmux cointrader-m4`），无 systemd/守护化，崩溃或重启后不会自动恢复。
4. **单实例锁实际失效**：`StateStore.acquire_lease()`（`src/cointrader/execution/store.py` L1010）TTL 30s；`refresh_lease()`（L1040）**全仓库无调用方**。锁 30 秒后过期，第二个进程可再取锁 → 守护化后存在双实例并发风险。
5. 状态持久化已较完整：SQLite 事件账本（`execution.store.StateStore`，schema v1，含 `run_sessions`/`orders`/`fills`/`pair_executions`/`signal_decisions`/`pnl_ledger`/`runtime_state`）；启动时 `LiveService.startup()` 做时钟校准→规则/杠杆预检→对账→用户流，`_refresh_held()` 以交易所真实持仓为准恢复 held 集合。**"重启后从交易所+账本恢复"的骨架已存在**，缺的是：锁续期、tick 异常容错、中断会话标记、跨 run 的 PnL/状态查询、守护化。
6. 模式切换现状：`execution.mode`（config：`paper/testnet/shadow/live`）+ `COINTRADER_USE_TESTNET` + `COINTRADER_TRADING_ENABLED`（魔法串）+ `--confirm-live`；端点由 `secrets.use_testnet()` 决定（`api.spot_testnet_base` 当前指向 demo.binance.com）。切换靠改 `config.yaml` + 环境变量，**无单点覆盖入口**。
7. `live pnl` / `live report`（`src/cointrader/cli.py`）默认取 `latest_run_session()`，**重启后默认视图只剩最新一次 run**，历史 run 只能 `--run-id` 查。跨 run 聚合不存在。
8. `cmd_live_run` 无 SIGTERM 处理：systemd `stop` 只能等 `TimeoutStopSec` 后 SIGKILL，会丢优雅停机（关流/释放锁/关闭 run_session）。
9. 日志已轮转（`logging_setup.setup_logging`：RotatingFileHandler 10MB×5）。
10. 测试基线：`uv run pytest` 600 passed；`ruff check src tests`、`mypy src/cointrader` 全绿（`docs/开发日志.md`）。
11. 依赖方向硬约束：`data/`、`research/`、`backtest/` 不得 import `execution/`；`tests/test_safety.py` 静态验证。本计划不触碰该边界。
12. ruff 关键规则生效：`S`（bandit）、`BLE`（禁裸 except，需 `# noqa: BLE001` 并注明理由）、`DTZ`（带时区 datetime）、`N`（命名）。新代码必须过这些规则。

### 模块边界

### 数据/控制流（长跑 + 断点重连）

```text
                 ┌──────────────────────────────────────────────┐
 systemd ─SIGTERM► cmd_live_run (signal handler → 优雅停机)      │
   │  (崩溃)      └──────────────┬───────────────────────────────┘
   ▼ Restart=always              │ run_forever(tick=5s)
 [重启预检] ◄─ kill -9 / 断电    │   try: run_once()
 startup():                      │   except Exception: enter_recovery + 连续计数
  1. acquire_lease(30s TTL)      │   连续计数 ≥ max → stop() → return False(退出码1)
  2. mark_interrupted_sessions() │
  3. 时钟校准 / 规则 / 杠杆预检   │ 每轮: refresh_lease()（锁长期有效）
  4. 对账(与交易所) → 恢复 held   │
  5. 用户流(poll) → 新 run_session│
   ▼                             ▼
 SQLite 事件账本（跨进程/跨重启持久，历史数据零丢失）
   orders / fills / pair_executions / signal_decisions /
   funding_cashflows / pnl_ledger / run_sessions(含 INTERRUPTED)
   ▲ 查询出口: live status(连续性块) / live pnl --all-runs / live report --run-id
```

### 状态生命周期与错误路径

- **状态拥有者**：`LiveService._state`（进程内）+ `runtime_state` 表（持久化镜像）+ `run_sessions` 表（会话账）。
- **run_session**：`startup()` 开新（`RUNNING`）；`stop()` 优雅关闭（`STOPPED`）；**新行为**：下次 `startup()` 把所有 `ended_ms IS NULL` 的会话补记为 `INTERRUPTED`。一个账本可有多条会话，PnL 按 run_id 归属，聚合跨 run。
- **lease**：`acquire` 时写入（holder=`pid-<pid>`，TTL 30s）；**新行为**：`run_once()` 每轮 `refresh_lease`（lease_holder 为空时跳过，保护单测）；`stop()` 时 `release_lease`。kill -9 场景由 TTL 过期回收（≤30s）。
- **tick 异常**：单轮异常 → RECOVERY + 告警 + 计数+1；任一轮成功 → 计数清零；计数 ≥ `max_consecutive_tick_errors` → 优雅 `stop()` 后以退出码 1 结束，由 systemd `Restart=always`（含 `StartLimitBurst` 崩溃频控）接管重启。
- **RECOVERY**：语义不变（禁开新仓、只允许减仓）；不自动解除（非目标）。
- **失败时用户看到什么**：日志（stderr → journald + `logs/cointrader.log` 轮转）+ 告警回调（`_on_alert`）；历史数据始终保留在 SQLite；`live status`/`live pnl --all-runs` 可查。
- **兼容性**：旧库无需迁移（不加表/列）；`end_run_session` 的幂等守卫（`ended_ms IS NULL OR ? >= ended_ms`）已保证重复停机安全；`stop()` 需保持幂等（run_forever 失败路径与 finally 可能各调一次）。

## 9. 安全、性能、兼容与回滚

- 输入校验与安全：`COINTRADER_EXEC_MODE` 精确白名单校验；`live` 模式三重闸门（魔法串 env + `USE_TESTNET=false` + `--confirm-live`）**零改动**，由 `tests/test_safety.py` 兜底；新 env 读取集中在 `cli._resolve_live_mode` 单点。
- 敏感信息：不新增任何密钥读写路径；`deploy/` 文件禁止出现密钥/个人路径（verify 子命令对渲染产物做占位符残留检查；提交前人工确认）。`.env` 不进仓库（已在 .gitignore）。
- 资源上限：`StartLimitBurst=12`/`StartLimitIntervalSec=600` 防崩溃循环打满日志与限频；`RestartSec=10` 防快速重启惊频交易所；tick 异常阈值 10（≈50s 持续故障才交给 systemd）；日志轮转沿用 10MB×5；lease 刷新每 5s 一次，SQLite 单行 UPDATE，开销可忽略。
- 性能：不改变主循环轮询频率与请求量（`refresh_lease` 是本地 DB 操作，不产生交易所请求）。
- 兼容性与迁移：无 schema 迁移（不加表/列）；旧库直接可用；`run_forever` 返回值变化仅影响唯一调用方（同批修改）；`paper`/回测/研究链路零改动；对既有 tmux 运行方式完全向后兼容（不装 systemd 也能照旧 `live run`）。
- 失败恢复：tick 异常 → RECOVERY（既有人工恢复流程）；持续故障 → 退出码 1 → systemd 重启 → 启动预检+对账（AC-03 闭环）；KILL_SWITCH 急停不变。
- 回滚：
  1. 服务器侧：`deploy/install-systemd.sh uninstall --project-dir <dir>`（disable + 删 unit + daemon-reload），回到 tmux 手工运行方式；
  2. 代码侧：`git revert` 本计划的提交（允许提交文件均独立于用户已有改动；`config/config.yaml` 仅新增一行，revert 不丢 `slippage_per_leg` 改动——执行模型提交时不得把用户未提交的 `slippage_per_leg`/README 改动并入本次提交，见第 11 节）；
  3. 数据侧：无迁移，无需数据回滚。

## 10. 偏离与停止规则

### 允许的小偏差（记录到根目录 `开发日志.md`，不停止）

- 测试实现细节：fake 适配器字段、monkeypatch 位置、临时库路径，只要验收行为不变；
- `for_run` 内部提取共享方法的私有命名/拆分方式（外部行为逐字段不变）；
- 日志/告警文案措辞（保留【】前缀与关键变量值）；
- unit 文件非契约字段（如 `Documentation=` 注释行）的增删；
- 等价重构：不改变公开 API、配置字段、数据模型、依赖与文件范围。

### 重大偏离（写入 `开发日志.md` 后**停止**，等待计划模型/用户裁决）

- 新增 Python 依赖或新增数据库/表/列（任何 schema 迁移）；
- 修改 `execution/guard.py`、`risk_gate.py`、`secrets.py` 的闸门语义或 `test_safety.py` 的静态约束；
- 改变 `execution.mode`/KILL_SWITCH/魔法串的既有行为或绕过路径；
- 改动 `data/`、`research/`、`backtest/` 层或引入跨层依赖；
- 改动策略/风控/成本参数值；
- 超出第 6 节文件变更表新增/修改/删除文件；
- 改变任何 AC 的可观察行为。

### 阻塞（写入 `开发日志.md` 后**停止**）

- 目标部署机无 systemd（假设 A2 不成立）且用户未指定替代守护方式；
- 工作区出现本计划无法安全区分的他人未提交改动（尤其 `service.py`/`cli.py`/`store.py` 出现计划外 diff）；
- 既有测试在改动前就非绿（基线被破坏，先报告，不自行修复无关失败）；
- 必要验证命令无法执行（如 `uv sync` 失败且非网络瞬时问题）；
- 发现 `refresh_lease`/`mark_interrupted_sessions` 的实现需要修改 `StateStore.__init__` 或连接生命周期语义。

低级执行模型无权批准重大偏离或重写本计划。
